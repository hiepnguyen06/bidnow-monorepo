# BidNow Monorepo Restructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current repo into the `bidnow-monorepo` layout (`apps/`, `services/`, `infra/`, `docs/`), add a static `apps/landing` showcase site, and push it to `hiepnguyen06/bidnow-monorepo` with history intact.

**Architecture:** Pure `git mv` of existing folders (so history follows), then path fixes in compose, CI, Docker and docs, then a new self-contained Next.js static-export app for the showcase, then a gated push. No monorepo build tool; each folder keeps its own build.

**Tech Stack:** Git, Maven (Java 17), Next.js 16 / React 19 / Tailwind / Vitest, Docker Compose, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-22-monorepo-restructure-design.md`

## Global Constraints

- Work on new branch `refactor/monorepo-structure`, created from the current branch `feature/browse-redesign`.
- Public repo `hiepnguyen06/bidnow-monorepo`. Push only `main` (= the restructured branch tip) and `develop`, plus tags. **No `dependabot/*` branches. No other branches.**
- Delete `.github/dependabot.yml` and `.github/workflows/dependabot-auto-merge.yml`; remove other Dependabot mentions.
- Remove the `common-resources` submodule, `.gitmodules`, and every mention of `/common-resources` (incl. AGENTS.md directive 2 and README). Remove empty `rules/`.
- Layout: `apps/web`, `apps/landing`, `services/` (Maven parent pom + 8 services + `common` + `bdd-support`), `infra/terraform/` (README only), `infra/local/` (compose + postgres init), single `docs/`.
- No Terraform, no AWS decisions, no AI/MCP folders, no Nx/Turborepo.
- `cd-deploy.yml` stays disabled (`if: false`), paths updated.
- Never commit, create the GitHub repo, or push without the owner's explicit go-ahead at that moment (checkpoints below). Conventional commits per CONTRIBUTING.md, e.g. `refactor(repo): move backend to services`.
- Web app landing link: env `NEXT_PUBLIC_LANDING_URL`, with a placeholder default; `/about` in the web app redirects to it.
- Secret scan: only real credentials are findings; local-dev defaults (`bidnow/bidnow`) and `.env.example` placeholders are not.
- Windows + OneDrive: stop dev servers/IDE indexers first; use `git mv`.

## Review Focus

1. `/about` hit on the web app (old bookmarks) must redirect, not 404.
2. `NEXT_PUBLIC_LANDING_URL` unset must yield the placeholder URL, never `undefined` in a link.
3. Path-filtered CI must actually match the new folders (a filter matching nothing makes CI silently skip).
4. Every compose `build.context` and Dockerfile `COPY` must resolve from `infra/local/` after the move.
5. Landing site must build and render with no backend, no env vars, and no auth/store code.
